# desk

Локальная Kanban-доска для AI-агентов. Данные хранятся в `.desk/`, агенты работают через MCP, а человек — через веб-интерфейс.

## Установка

```bash
npm install
npm run build
npm i -g .
```

## Подключение к проекту

```bash
cd ~/projects/my-app
desk init --claude-md
```

Команда создаёт `.desk/project.yaml`, `.desk/board.yaml`, `.desk/tasks/`, подключение в `.mcp.json` и, с флагом `--claude-md`, добавляет правила работы с доской.

## Tenant и project

Идентичность данных имеет вид `tenant → project`. Она хранится в `.desk/project.yaml`:

```yaml
version: 1
tenant_id: local
project_id: my-app
name: "My app"
```

Один проект по-прежнему полностью работает в локальном режиме: board, задачи, locks и events читаются только из его `.desk/`. Старые проекты без `project.yaml` автоматически получают legacy-контекст `tenant_id: local` и идентификатор из имени каталога; `desk init` создаёт явный metadata-файл без изменения существующих задач.

Чтобы добавить новый проект, перейдите в его корень и выполните `desk init`. Для существующего проекта сначала сохраните резервную копию `.desk/`, затем добавьте `project.yaml` с уникальной парой `tenant_id`/`project_id` и проверьте результат через `desk validate`. Данные не переносятся и не смешиваются: namespaced HTTP-маршруты имеют вид `/api/tenants/:tenant/projects/:project/...`, а MCP-инструменты принимают необязательный контекст `tenant_id` и `project_id`.

Сейчас один запущенный экземпляр desk обслуживает один project root. UI показывает активный tenant/project и готов к нескольким проектам, когда появится внешний registry; до этого переключатель отключён, если доступен только текущий проект.

## Команды

```text
desk init [--claude-md] [--hooks]  создать доску (и подключить хуки Claude Code)
desk mcp                           запустить MCP-сервер по stdio
desk ui [--port N] [--open]        открыть локальную веб-доску
desk validate                      проверить board.yaml и задачи
desk hooks install                 добавить хуки сабагентов в .claude/settings.json
desk hook agent-start|agent-attach|agent-end  обработчики хуков (Claude Code вызывает их сам)
```

По умолчанию UI доступен на `http://127.0.0.1:4717`.

Задачи — Markdown-файлы с YAML-заголовком. Правила колонок, полей, переходов и WIP-лимитов задаются в `.desk/board.yaml`.

## Сабагенты на доске

Хуки Claude Code делают работу сабагентов видимой на доске: каждый вызов инструмента `Agent` (старое имя `Task`) получает свою карточку.

```bash
desk hooks install     # или сразу: desk init --claude-md --hooks
```

Команда дописывает в `.claude/settings.json` проекта (запись атомарная; остальные настройки и хуки не трогаются, повтор ничего не дублирует):

| Событие | matcher | Команда | Что делает |
|---|---|---|---|
| `PreToolUse` | `Agent\|Task` | `desk hook agent-start` | создаёт карточку и запоминает запуск |
| `SubagentStart` | — | `desk hook agent-attach` | связывает карточку с `agent_id` и передаёт сабагенту её номер |
| `PostToolUse` | `Agent\|Task` | `desk hook agent-end` | закрывает карточку (для фоновых — только запоминает запуск) |
| `SubagentStop` | — | `desk hook agent-end` | закрывает карточку по `agent_id` |
| `PostToolUseFailure` | `Agent\|Task` | `desk hook agent-end` | вызов упал — карточка возвращается в первую колонку |
| `PermissionDenied` | `Agent\|Task` | `desk hook agent-end` | вызов отклонён auto mode — карточка возвращается в первую колонку |

Хуки **ничего не одобряют и не меняют ввод инструмента**: `PreToolUse` ничего не печатает, права и промпты Claude Code работают как обычно.

1. **Запуск.** `agent-start` создаёт карточку от имени `claude-code`: заголовок — `description` вызова (или первая строка промпта), в описании — тип сабагента и промпт (до 1500 символов). `assignee` — `name` из вызова, если он задан, иначе тип сабагента без `:`; полный тип (например `ecc:code-reviewer`) хранится во встроенном поле `agent` и виден на карточке мелкой строкой под заголовком и в шапке панели задачи. Карточка переносится в `in_progress` (или во вторую колонку). Если доска не пускает (WIP-лимит, обязательные поля), карточка остаётся в первой колонке с заметкой `hook: не удалось взять в работу — …`.
2. **Что видит агент.** На `SubagentStart` desk находит самый старый ожидающий запуск той же сессии и того же типа, добавляет заметку `hook: сабагент запущен (<agent_id>)` и передаёт сабагенту через `additionalContext` строку: `Твоя карточка на доске desk: T-012. Пиши ход работы через MCP tool add_note(id: "T-012", actor: "Explore"). Не создавай для этой работы новую карточку.` Правило из `desk init --claude-md` подсказывает найти карточку через `list_tasks`, если строки нет.
3. **Завершение.** `agent-end` добавляет заметку `hook: сабагент завершил работу — <первая строка ответа>` и переносит карточку в последнюю колонку. Если доска этого не позволяет — заметка `hook: перенеси вручную — …`, карточка остаётся на месте. Фоновые сабагенты (по умолчанию в новых Claude Code) закрываются по `SubagentStop`. При сбое или отказе вызова появляется заметка `hook: вызов не выполнен — <причина>`, и карточка возвращается в первую колонку.
4. **Уборка.** Запуски, которые за 6 часов так и не получили `SubagentStart`, при следующем `agent-start` удаляются из карты с заметкой `hook: запуск не подтверждён`.

Связь «вызов → карточка» хранится в `.desk/.agent-runs.json` (последние 500 запусков, файл в `.gitignore`). Хуки никогда не блокируют Claude Code: при любой проблеме они пишут сообщение в stderr и завершаются с кодом 0. Команда `desk` должна быть доступна в `PATH` (`npm i -g .`).

Перед релизом проверьте:

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
desk validate
```
